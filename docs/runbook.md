# Runbook: Vendored docling-baseline Generator

This runbook covers operating the vendored `docling-baseline` baseline-fixture
generator that lives at `src/docling_baseline/`: its provenance, the dependency
isolation guarantee, the two CI guards (and exactly what to do when each fires),
and how to invoke the generator on Python 3.13.

## Vendoring Provenance

There are two copies of the generator, with distinct roles:

- `references/docling-baseline/` -- the **read-only** upstream source of truth.
  Nothing in `doc-bench` imports from it. It exists for provenance and to make
  re-syncing the verbatim copy auditable.
- `src/docling_baseline/` -- a **verbatim** copy of
  `references/docling-baseline/src/docling_baseline/`. It is intentionally NOT
  conformed to `doc-bench` lint, type, or formatting standards; it is byte-for-byte
  the upstream generator. It is excluded from ruff, black, mypy, and coverage in
  `pyproject.toml`, and is never included in the wheel.

When re-vendoring, copy from `references/docling-baseline/` byte-for-byte. Do not
hand-edit `src/docling_baseline/` to satisfy `doc-bench` tooling.

## Dependency-Group Isolation Guarantee

The generator's heavy dependencies (`docling` pulls a full torch tree, plus
`docling-core`, `apted`, `rapidfuzz`, `beautifulsoup4`, `lxml`, `nltk`,
`sacrebleu`, `jsonschema`, `polars`, `click`, `pydantic`, `beartype`) live ONLY
in the dev-only `generator` dependency-group in `pyproject.toml`. They are
deliberately absent from `[project.dependencies]` and from the `[docling]`
runtime extra (which carries only `docling>=2`).

Guarantee: a no-group `uv sync` produces a clean default environment that does
NOT contain `docling` or `docling-core`. Verify:

```bash
# Default env: docling / docling-core must NOT be present.
uv sync
uv run python -c "import importlib.util as u; \
assert u.find_spec('docling') is None and u.find_spec('docling_core') is None, \
'generator deps leaked into the default env'; print('isolation OK')"

# The generator deps are reachable only via the explicit group:
uv run --group generator python -c "import docling; print('generator group OK')"
```

The structural assertions are enforced by
`tests/test_generator_dependency_isolation.py` (fast suite).

## Generator Invocation (Python 3.13)

The generator assumes Python 3.13; `doc-bench` core stays `requires-python
>=3.12`. `uv` auto-provisions the 3.13 interpreter. Invoke the generator as a
module under the dev group:

```bash
# All in-scope datasets (DP-Bench + OmniDocBench), in-place:
make regen-fixtures

# A single dataset:
make regen-fixtures DATASET=dp_bench

# The underlying command both targets run:
uv run --python 3.13 --group generator python scripts/regenerate_fixtures.py
```

`scripts/regenerate_fixtures.py` invokes the generator as a module
(`python -m docling_baseline.cli <dataset> <fixtures_dir>`), runs in-place
against `src/doc_bench/fixtures/`, and applies the DP-Bench rename on copy
(`dp_bench_results.json` becomes `dpbench_results.json`; `omnidocbench_results.json`
passes through unchanged). ATO-Bench is out of scope and is never regenerated by
this script.

## Guard: Byte-Equality Drift Guard

- Test: `tests/test_metric_drift_guard.py`
- Where it runs: the fast suite (`make test` / `uv run pytest`), and therefore in
  CI via the `ci` target's `test` step. No Docling install required.

### What it enforces

The verbatim vendoring keeps a second copy of the metric implementations and the
parser-output schema. This guard asserts each vendored file is byte-identical to
its `doc-bench` counterpart:

- `src/docling_baseline/metrics/{mhs,reading_order,text_similarity}.py` and
  `src/docling_baseline/schemas/parser_output.schema.json` are compared
  byte-for-byte against `src/doc_bench/metrics/parsing/*.py` and
  `src/doc_bench/fixtures/parser_output.schema.json`. These carry NO allow-listed
  delta.
- `nid.py` and `table_teds.py` have an explicit, pinned allow-list entry each:
  the deprecated legacy-alias function `doc-bench` appends for backward
  compatibility (`normalized_indel_distance` on `nid.py`; `table_teds` on
  `table_teds.py`). The shared core scoring logic must still match the vendored
  copy (byte-identical for `nid.py`; token-identical, allowing whitespace reflow,
  for `table_teds.py`).

The allow-list contains EXACTLY those two legacy-alias deltas and nothing else.

### What to do when it fires

1. Read the failure message; it names the diverging file and whether the
   divergence is in a byte-identical file, in a pinned alias suffix, or in the
   shared core token stream.
2. Determine intent:
   - **Unintended drift** (a metric bug was fixed in one copy but not the other):
     re-sync the two copies so they match again. The fixture baselines must be
     reproducible by the `doc-bench` scorer that ships in the wheel.
   - **Intended change** to a `doc-bench` metric: mirror the same change into the
     vendored copy (`src/docling_baseline/metrics/...`) so the two stay in lock
     step, OR -- only after explicit review -- deliberately update the pinned
     allow-list in `tests/test_metric_drift_guard.py` (the `ALLOW_LIST` entries
     and/or `BYTE_IDENTICAL` tuples) to record the new, reviewed delta with a
     precise reason.
3. Never widen the allow-list to silence an unreviewed divergence; that defeats
   the guard.

## Guard: Wheel-Leak Guard

- Test: `tests/test_wheel_no_generator_leak.py`, marked `build`.
- Where it runs: deselected from the default fast loop; run explicitly.

```bash
uv run pytest -m build
# or
make test-build
```

The `ci` target runs `make test-build` after the fast suite, so this guard is
enforced in CI even though it is excluded from `pytest -q`.

### What it enforces

It builds the wheel and inspects the artifact
(`python -m zipfile -l dist/*.whl`), asserting:

- ZERO `docling_baseline` paths are present in the wheel (the verbatim generator
  must never ship to consumers), and
- `doc_bench` paths ARE present (the build produced something usable).

### What it means when it fails

The vendored generator leaked into the distribution. Inspect
`[tool.hatch.build.targets.wheel]` (`packages = ["src/doc_bench"]`) and
`[tool.hatch.build]` `include` globs in `pyproject.toml`: they must stay scoped
to `src/doc_bench/**` and must NOT add any `include` entry that matches
`src/docling_baseline`. Remove whatever broadened the wheel scope, rebuild, and
re-run `uv run pytest -m build`.
